# SecureBoost 环境与运行说明

## 1. 已验证环境

本项目在 WSL2 Ubuntu 的 `secureboost-sf` Conda 环境中验证，使用 Python
`3.10.20` 和 SecretFlow `1.13.0b0`。运行时依赖固定在项目根目录的
`requirements.txt`，其中包含 SecretFlow、Ray、NumPy、Pandas、scikit-learn
和 pytest 的已验证版本。

在 WSL 项目根目录执行：

```bash
conda activate secureboost-sf
cd /mnt/c/Users/yybq/Desktop/work/secretflow

python --version
python -c "import secretflow as sf; print(sf.__version__)"
python -m pytest -q
python cases/toy_case.py
python cases/breast_cancer_case.py
```

VS Code 应通过 Remote - WSL 打开该目录，并选择解释器：

```text
/home/yybq/miniconda3/envs/secureboost-sf/bin/python
```

## 2. 依赖边界

`requirements.txt` 是当前项目的最小、已验证运行集合，并不安装 SecretFlow
所有可选业务组件。当前环境可以导入 SecretFlow、创建 HEU、运行两方
SecureBoost、保存/加载模型，并通过项目测试。

同时，`python -m pip check` 会报告 SecretFlow 包元数据中声明但当前未安装的
组件，例如 TensorFlow、Torch、ONNX、XGBoost、NetworkX 和 `validator-py`。
因此不得把当前环境描述为“SecretFlow 全量功能环境”。这些依赖并非当前案例
路径的直接运行前提，但在后续使用神经网络、ONNX、Torch 或其他相关组件前，
必须依据目标组件的官方兼容要求单独建立并验证环境。

不要为了消除 `pip check` 提示而盲目安装全部缺失包：它们体积较大，且可能改变
当前经验证的 NumPy、JAX、Ray 和 Python 组合。新增组件时应先创建新环境，
再完成单独的兼容性验证。

## 3. 复现验收

一次完整运行应满足：

- `pytest -q` 全部通过；
- 两个案例的日志文件非空；
- `outputs/metrics/` 中有玩具数据、Breast Cancer、对比和审计 JSON；
- `outputs/models/` 中存在 Alice/Bob 的模型分片；
- Breast Cancer 结果的 AUC 不低于 `0.90`，并与集中式参考结果一起解释。

该说明只覆盖本项目的单机仿真环境，不覆盖跨机构生产部署、PSI、证书、密钥
轮换或高可用配置。
